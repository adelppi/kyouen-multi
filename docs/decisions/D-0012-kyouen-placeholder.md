## 背景

#18 と #19 で、完成した円の判定と、石を置ける場所の計算を実装した。adelppi から、これらのアルゴリズムはほかの開発メンバーが考えるので、プレースホルダーにするよう求められた。これまでの実装の方法は、ドキュメントに残してよいとされた。

## 決定

- `lib/kyouen.ts` の `findKyouen` と `findSafePoints` を、空の配列を返すプレースホルダーにする。ほかの開発メンバーが、この2つの関数の中身を作る。
- チェックボックス、表示の切り替え、結果を盤面に描く処理は残す。2つの関数が結果を返すようになれば、そのまま盤面に描かれる。
- 結果の形と、結果を描くための関数（`circleOf`、`clipLine`）は残す。
- `kyouen-display.md` と `safe-points.md` の状態を「合意」に戻す。

### 関数の形

- `findKyouen(stones)`: 石のある格子点のキー（`"x,y"`）を受け取り、4つ以上の石を通る円と直線を返す。1つの円か直線を `{ curve, points }` で表す。`curve` は a(x²+y²) + bx + cy + d = 0 の係数 `{ a, b, c, d }` で、a が 0 なら直線を表す。`points` は、その円か直線の上にある石の格子点。
- `findSafePoints(size, stones)`: 盤面のサイズと、石のある格子点のキーを受け取り、石を置ける場所の格子点を返す。

### これまでの実装の方法

コードは、判定がコミット 5d8ddf7、置ける場所の計算がコミット 2b5ace6 にある。

完成した円の判定は、次の手順で計算していた。

1. [共円のルールと用語](../specs/kyouen-rules.md)の判定の行列式を、1行目を (x²+y², x, y, 1) として展開する。3つの格子点を残りの3行に入れると、その3点を通る円か直線の式 a(x²+y²) + bx + cy + d = 0 の係数が、3次の行列式で求まる。係数はすべて整数になる。
2. 4つの係数を最大公約数で割り、最初の 0 でない係数が正になるように符号をそろえる。こうすると、同じ円や直線は、どの3点から求めても同じ係数になる。3点に同じ格子点が含まれて係数がすべて 0 になるときは、円も直線も決まらないので除く。
3. 石の3つ組をすべて調べ、係数ごとに、その係数を作った石を集める。石の数を n とすると、3つ組は n(n−1)(n−2)/6 通りある。
4. 4つ以上の石が集まった係数を共円とする。

石を置ける場所は、次の手順で計算していた。

1. 上の手順 1〜3 で、1つ以上の3つ組から求まった係数（3つ以上の石を通る円と直線）をすべて集める。
2. 石のない格子点ごとに、集めた式のどれかを満たすかを調べる。どれも満たさない格子点を、置ける場所とする。すでにできている共円の式を満たす格子点も、置けない場所になる（D-0010）。

盤面に描くときは、次のように計算する。この処理は残している。

- a が 0 でなければ円として、中心 (−b/2a, −c/2a)、半径 √(中心の x² + 中心の y² − d/a) で描く。
- a が 0 なら直線として、盤面の四角形との交点を両端にして描く。
