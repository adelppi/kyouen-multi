# D-0017 参加者の一覧をドラッグで並び替え、部屋で共有する

- 日付: 2026-10-20
- 決めた人: adelppi
- 関係する Issue と PR: #50
- 解決した未解決の項目: なし
- 置き換える記録: なし

## 背景

参加者の一覧は、部屋に入った順（connection ID の順）に並び、並び替えられなかった。adelppi から、ドラッグで並び替えられるようにして、並び順を部屋で共有したいと依頼があった。

## 決定

- 参加者の一覧は、ドラッグで並び替えられる。部屋の誰でも、自分以外の参加者も含めて並び替えられる。
- 並び順は部屋の全員で共通にする。一人が並び替えると、ほかの参加者の一覧も同じ順になる。
- 並び順は Liveblocks の Storage に、connection ID の並びとして、操作の記録とは別に置く。
- 並び替えたときは、そのとき部屋にいる参加者だけで並び順を書き直す。抜けた参加者は並び順から除く。
- 並び順に入っていない参加者は、並び順に入っている参加者のあとに、部屋に入った順に並べる。並び替えのあとで部屋に入った参加者は、一覧の末尾に付く。
- 再読み込みなどで入り直すと、connection ID が変わるので、一覧の末尾に移る。
- 並び順で参加者の色は変えない。色は D-0008 のとおり connection ID から選ぶ。
- 並び替えは操作の記録と履歴に入れず、undo と redo の対象にしない。
- ドラッグは、マウスとタッチで同じ処理になるように、ポインタのイベントで作る。

## ほかの選択肢

- 並び順を参加者ごとにする案。依頼に合わないので採らなかった。
- 並び順を Liveblocks の user ID（ブラウザごとの ID）の並びで置く案。入り直しても位置が残るが、同じブラウザで2つのタブを開くと2人が同じ ID になる。色と同じく connection ID にそろえるほうが単純なので採らなかった。困ったら見直す。
- 並び替えを操作の記録に入れる案。D-0016 と同じく、undo で並び順が変わり、履歴に盤面と関係のない行が並ぶので採らなかった。
- HTML の drag and drop の API を使う案。マウスとタッチで同じ処理にしやすいポインタのイベントを選んだ。

## 根拠

- ドラッグで並び替えること、並び順を部屋で共有することは、adelppi が依頼して決まった。
- 並び順を connection ID で置くこと、新しく入った参加者を末尾に付けること、記録に入れないこと、ポインタのイベントで作ることは Claude が決めた。
