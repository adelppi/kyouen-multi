- 日付: 2026-10-18

- 置き換える記録: なし

## 背景

AI 駆動開発の基盤として、次の5つを実現するドキュメントを `docs/` に置くことになった。

- Issue 駆動。機能ごとに1タスク1PR とし、ドキュメント、ソースコードの順に作る。
- 仕様駆動。ドキュメントとソースコードを常にそろえる。
- 未解決の項目。ドキュメントを考えている途中などで出た未解決の要件を書きためる。
- 決定の記録。決定の理由、背景、ほかの選択肢、根拠を書く。追記だけで、消さない。
- 要求と思想。誰のためのアプリか、どんな責務を持つか、何をして何をしないかをはっきりさせる。

## 決定

次の構成にする。

- `docs/vision.md`: 要求と思想
- `docs/workflow.md`: Issue から PR までの進め方と、仕様とコードをそろえる決まり
- `docs/specs/`: 機能ごとの仕様。1機能1ファイル
- `docs/open-questions.md`: 未解決の項目。1つのファイルにまとめる
- `docs/decisions/`: 決定の記録。1決定1ファイル
- `.github/ISSUE_TEMPLATE/task.md` と `.github/pull_request_template.md`: Issue と PR の形

`CLAUDE.md` から `docs/workflow.md` を参照し、Claude がこの進め方に従うようにする。

## ほかの選択肢

- 決定の記録を1つのファイルにまとめる案。全体を一度に読めるが、追記だけという決まりが差分から確かめにくく、並行する PR で衝突しやすいので採らなかった。
- 未解決の項目を1項目1ファイルにする案。項目ごとに状態が変わるので、一覧で状態を見渡せる1つのファイルのほうが扱いやすいと考え、採らなかった。

## 根拠

- 決定の記録を1決定1ファイルにすると、追記は新しいファイルを足すことになり、既存のファイルの変更が差分で目立つ。
- 未解決の項目は書き換え（状態の変更や移動）があるので、追記だけの決定の記録とは分けた。
