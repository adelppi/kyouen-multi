# 操作の記録と同期

- 状態: 下書き
- Issue: #6（仕様）、#12（実装）
- 関係する決定: [D-0004](../decisions/D-0004-tech-stack.md)、[D-0005](../decisions/D-0005-room-lifetime-and-board-size.md)

## 目的

参加者全員の操作に1つの順番を付け、全員の盤面を同じにする。`vision.md` の「同時の操作の競合を解決する」に当たり、undo と redo、履歴の前提になる。

## 振る舞い

1. 盤面を変える操作は、部屋ごとの記録に追記する。記録は Liveblocks の Storage の LiveList に置く。
2. 1つの操作は、種類、中身、操作した参加者の名前と色、操作した時刻を持つ。
3. 操作の種類は次のとおり。
   - 置く: 格子点を1つ指定する
   - 取り除く: 格子点を1つ指定する
   - リセット
   - サイズ変更: 新しいサイズを指定する
   - undo
   - redo
4. 盤面は、記録を先頭から順に当てはめた結果として、各クライアントが計算する。
5. 記録の順番で当てはめたときに盤面が変わらない操作は、何もしない操作として扱う。たとえば次の操作がこれに当たる。
   - すでに石がある格子点に置く
   - 石がない格子点から取り除く
   - 盤面の外の格子点を指定する
6. 2人がほぼ同時に操作したときは、記録の順番で決着させる。たとえば2人が同じ格子点に置いたら、記録で後になった操作は何もしない操作になる。
7. 記録から外したり、記録の中を書き換えたりしない。
8. 部屋を作ったときの盤面は、石がなく、サイズが 9×9 の盤面とする。
9. サイズ変更の操作は、盤面のサイズを変え、置いてある石をすべて取り除く。
10. 部屋の参加者が全員抜けたら、記録を消す（[D-0005](../decisions/D-0005-room-lifetime-and-board-size.md)）。

## 受け入れ条件

- [ ] 2つのブラウザで同じ部屋に入り、一方で置いた石がもう一方にも出る
- [ ] 2つのブラウザで同じ格子点にほぼ同時に置くと、両方の盤面で石が1つだけになる
- [ ] 部屋に入り直すと、記録から同じ盤面が再現される
- [ ] 同じ記録からは、どのクライアントでも同じ盤面が計算される（単体テストで確かめる）

## 範囲外

- カーソル（記録に入れない。`cursors.md` で扱う）
