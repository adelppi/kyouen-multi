# ドキュメント

共円マルチの開発で使うドキュメントの一覧と、それぞれの役割をまとめる。人も AI も、作業を始める前にここから読む。

## 一覧

| ファイル | 役割 | 書き換え |
|---|---|---|
| [vision.md](vision.md) | 誰のためのアプリか、責務、やること、やらないこと | 合意したうえで書き換える |
| [workflow.md](workflow.md) | Issue から PR までの進め方と、仕様とコードをそろえる決まり | 合意したうえで書き換える |
| [specs/](specs/README.md) | 機能ごとの仕様。コードはこの仕様に合わせる | 機能を変える PR で書き換える |
| [open-questions.md](open-questions.md) | まだ決まっていない要件や疑問 | 追記し、解決したら状態を変える |
| [decisions/](decisions/README.md) | 決めたことの理由、背景、ほかの選択肢、根拠 | 追記だけ。消さない |

## 読む順番

1. `vision.md` で、アプリの目的とやらないことを確かめる。
2. `workflow.md` で、作業の進め方を確かめる。
3. 作業する機能の仕様を `specs/` で読む。
4. 関係する未解決の項目を `open-questions.md` で、過去の決定を `decisions/` で確かめる。

## ドキュメント同士の関係

- `vision.md` は、仕様に入れるかどうかを決めるときの基準にする。「やらないこと」に当たる機能は仕様に入れない。
- 仕様を書いている途中で決められないことが出たら、`open-questions.md` に書く。
- 未解決の項目が決まったら、`decisions/` に決定を書き、`open-questions.md` の項目からその決定へリンクする。
- 仕様は決定の結果を書き、理由は `decisions/` へのリンクで示す。
